# Nosuha-Space-React
Веб-приложение на React и NodeJS про носуху, созданное в учебных целях.

## Запуск

Команды PowerShell из корня репозитория (зависимости уже установлены):

```powershell
Set-Location 'Coati Space Project/Client'
npm run build
Set-Location ../Server
npm start
```

Сайт: http://localhost:3000/stav-zoo. Сервер раздаёт сборку `Client/dist`
и ресурсы из корневой папки `Resource` по исходным адресам `/images` и `/videos`.
Порт сервера можно задать переменной окружения `PORT`.

## Разработка

В первом терминале из папки `Coati Space Project/Server` запустить `npm run dev`,
во втором из `Coati Space Project/Client` — `npm run dev`.
Открыть адрес Vite, указанный во втором терминале, с путём `/stav-zoo`.
Vite перенаправляет `/api`, `/account`, `/Zoo`, `/images` и `/videos` на `http://localhost:3000`;
при смене порта сервера нужно изменить адрес в `Client/vite.config.js`.

На этапах 4–5 перенесены публичные и служебные React-страницы и исходное оформление локальным CSS.
`/stav-zoo` открывает готовую главную зоопарка, `/stav-zoo/coati` — карточку носухи
со ссылкой возврата. Карточка получает описание и четыре последних заметки
из существующих текстовых API `/api/coati/info` и `/api/coati/diary`.
Ошибки API, формата ответа и загрузки медиа отображаются на странице.
Секция камеры, как в оригинале, содержит одно локальное видео с постером,
автовоспроизведением без звука и повтором. Галерея содержит 8 фотографий.
Форма `POST /Zoo/Donate` возвращает исходный редирект на CloudTips;
собственная обработка платежей и запись доната при редиректе не добавлены.
Сведения о вошедшем сотруднике передаются в HTML и управляют исходными
пунктами навигации как при запуске Express, так и в Vite.
`/account/login` и `/account/denied` отображаются React-компонентами.
Дневник доступен по исходным маршрутам `/diary`, `/diary/create`,
`/diary/edit/:id`, `/diary/delete/:id` только с ролью `Admin`.
Сохранены подтверждение удаления, сообщения результата и поля исходных форм.

Проверки: сначала `npm run build` из `Client`, затем `npm test` из `Server`.
Интеграционные тесты форм входа и дневника проверяют собранную HTML-оболочку React.

## База данных и авторизация

Требуется Node.js с встроенным `node:sqlite` (в текущем окружении — 26.13.0).
При первом запуске сервер создаёт `Server/coati.db` с исходными таблицами
`Coatis`, `DiaryEntries`, `Donations`, `StaffUsers` и начальными данными оригинала.
Повторный запуск сохраняет изменения и не восстанавливает удалённые seed-записи.
Ключ шифрования cookie хранится в `Server/.auth-key`; база и ключ исключены из Git.
Ошибка открытия/инициализации базы или чтения ключа прерывает запуск.

Исходная учётная запись: `admin` / `admin2026`, роль `Admin`.
Форма входа: `GET /account/login`; вход: `POST /account/login`
с полями `username`, `password`, `returnUrl` (URL-encoded форма).
Успешный вход устанавливает HttpOnly-cookie на 8 часов и возвращает 302
на локальный `returnUrl` либо `/diary`; выход `/account/logout` удаляет cookie
и перенаправляет на `/stav-zoo/coati`.
Отсутствующие поля дают 400, неверные данные или недействительная cookie — 401,
отсутствие прав администратора — 403. Тексты ошибок сохранены из оригинала.
Формы входа и отказа перенесены в React с исходной разметкой и локальным CSS.
При отказе в доступе к HTML-странице возвращается форма входа (401)
либо страница ограничения доступа (403); API возвращает JSON с описанием ошибки.

Текстовые API оригинала (`text/plain; charset=utf-8`):
`GET /api/coati`, `/api/coati/info`, `/api/coati/diary`,
`/api/coati/donations`, `/api/coati/status`.
При отсутствии особи `/api/coati` и `/api/coati/info` возвращают 404
с исходным сообщением об отсутствии данных.

## API служебного дневника

Все операции требуют cookie сотрудника с ролью `Admin`:

- `GET /api/diary` — список записей `Entries` и список сотрудников `Authors`.
- `GET /api/diary/:id` — одна запись с исходными полями модели.
- `POST /api/diary` — создание, статус 201 и `Id`, `SuccessMessage`.
- `PUT /api/diary/:id` — редактирование, статус 200 и `SuccessMessage`.
- `DELETE /api/diary/:id` — удаление, статус 200 и `SuccessMessage`.

Запросы создания/редактирования принимают исходные поля `Id`, `CoatiId`,
`EventDate`, `EventType`, `Title`, `Description`, `Author` в JSON.
Параметры фильтрации: `filterType`, `dateFrom`, `dateTo`, `author`.
Категория и сотрудник сравниваются точно; пустые значения и `Все` не ограничивают выборку.
Дата «от» включается с начала дня, дата «до» — целиком до начала следующего дня.
Записи сортируются по `EventDate` по убыванию. Сотрудники берутся из всех записей,
без пустых имён и повторов, с сортировкой, независимо от применённых фильтров.
Как в оригинале, «Уборка» есть в формах, но отдельной кнопки этого фильтра нет.

Неверные поля/фильтры дают 400 с `error` и `errors`, отсутствующая запись — 404,
ошибка БД — 500. Стандартные ошибки обязательности полей предшествуют
исходным сообщениям контроллера; форма показывает первое сообщение поля, как Razor.
Текстовые публичные API не изменены и отражают изменения дневника.
